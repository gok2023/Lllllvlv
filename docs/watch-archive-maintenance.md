# 观影档案维护验收

## 资产与操作

当前资产包括按服务和用户隔离的快照、独立媒体库修正文件、用户导出的版本化 JSON、手动指定的 Playback Reporting 路径。快照内有媒体目录、逐次播放、补录及固定基线、确认、待处理候选、已应用操作和撤销 ID、人工身份关联、设置、媒体库目录及同步游标。路径文件不随观影档案导出；迁移设备时须重新核对本机数据库路径。

版本 3 导出包含快照和修正；导入兼容版本 1、2、3，以及本程序生成的原始快照 `.backup` 文件。预览显示各类数量及同 ID 不同内容的冲突数。预览后若文件、当前档案或服务用户改变，确认导入会拒绝，须重新选择和预览。无冲突合并按稳定 ID 去重，保留两边独有资产；冲突时拒绝合并。替换采用导入档案，写入前备份当前快照及修正，写入失败时尝试回滚。原子重命名减少写入中断风险，不提供停电持久性保证。人工关联只在用户确认两项同源同类型作品后保存；标题相同不是自动关联证据。具体持久化契约见 [观影统计](watch-statistics.md)。

默认档案目录是 `%APPDATA%\Freebo\watch-statistics\`；若在「设置 → 常规」选择了自定义数据目录，则到该数据目录下的 `watch-statistics\`。当前快照为 `<serverId>-<normalizedUserId>.json`，导入前自动备份是同名文件后接时间戳和 UUID、以 `.backup` 结尾，日常自动备份以 `.auto.backup` 结尾。导入前备份包含写入前的快照与修正；日常备份只在相关写入流程触发，不保证首次启动或升级前自动创建。最多保留最近五份导入前备份和五份日常备份；重要版本应另行导出并保存。

操作顺序：先用「导出数据」保存当前用户档案；在目标服务网页登录正确用户；用「导入数据」选择版本化 `.json` 或上述原始 `.backup`，检查预览的数量、时间范围、冲突和媒体库修正警告；按需要选择合并或替换；完成后核对确认、补录、修正和统计范围，再执行完整同步。要回退一次导入，在同一服务和用户下重新选择那次导入前生成的 `.backup`，预览后选择「导入并替换」，无需编辑 JSON。跨设备媒体库 ID 可能不同，修正是否仍指向目标媒体库须人工核对。真实用户档案、安装版和跨设备操作均未由本报告自动执行。

## 检查记录与边界

仍未覆盖：真实 Jellyfin 与 Playback Reporting、安装版和跨设备恢复；目标媒体库 ID 不同后的修正人工核对；插件不可用后的导入组合；同步写入故障注入；导入完成后通过完整页面交互核对各范围统计。预览数量中的新增、重复只统计播放记录，已有映射与待关联项是身份映射概况，不代表所有确认或修正已自动解决。

本轮尚未连接真实 Jellyfin、用户数据、安装版或稳定 ETLP。`node --check web/watch-statistics.js`、直接运行 `tsc --noEmit`、`vite build`、`node scripts/build-electron.mjs` 通过。统计专项 `watch-statistics-archive.test.ts`、`watch-statistics-refresh.test.ts`、`watch-statistics-periods.test.ts` 共 29 项合成测试通过；页面 fixture 使用固定 2026-11-16 本地时间和跨日实播。全套 Vitest 首次在沙箱内为 45 文件通过、1 文件失败：256 项通过、3 项失败、1 项跳过；失败均在原有 `media-proxy.test.ts`，原因是沙箱禁止连接 `127.0.0.1:6549`（`EACCES`）。自动审批后在沙箱外单独重跑该文件，3 项全部通过。`pnpm typecheck` 因沙箱外 pnpm store 建立符号链接时 `EPERM` 未启动。矩阵剩余边界须随隔离测试结果补充具体命令、fixture 与断言后再标为通过。
